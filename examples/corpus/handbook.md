# 內部工程手冊（示範用語料）

## 部署流程

正式環境的部署一律走 GitOps。開發者把變更推到 main 之後，CI 會產生映像檔並更新
deploy repo 的 image tag，ArgoCD 偵測到差異後自動同步。**不要直接 kubectl apply
到正式環境**，那會被下一次同步覆蓋掉。

緊急修復（hotfix）例外：可以由值班工程師執行 `make emergency-deploy`，但事後
二十四小時內必須補一個 PR 回填變更，否則會在下次同步時遺失。

## 資料庫遷移

遷移腳本放在 `db/migrations/`，用 Alembic 管理。規則：

- 一個 PR 只能有一個遷移檔，避免衝突難解
- 所有遷移必須可回滾，`downgrade()` 不可以留空
- 加欄位一律先加 nullable，回填資料之後再改成 not null，分成兩次部署做完
- 刪欄位要先經過一個完整的部署週期把程式碼的引用清乾淨，才能刪

正式環境的遷移由 CI 在部署前自動執行，不需要手動跑。

## 監控與告警

服務指標送到 Prometheus，儀表板在 Grafana。告警規則寫在 `monitoring/alerts.yaml`。

值班的判斷原則：**P1 是有使用者受影響且無法自行繞過**，十五分鐘內要有人回應。
P2 是功能降級但有替代路徑，四小時內處理。P3 排進下個 sprint。

不要為了讓儀表板好看而調高告警閾值。如果某條告警一週響超過三次而每次都不是真
問題，該做的是修那條規則或修那個服務，不是把閾值往上調。

## 程式碼審查

每個 PR 至少需要一位 reviewer 核准。審查重點依序是：正確性、可測試性、可讀性。
效能只有在有量測數據支持時才拿出來討論。

PR 超過四百行就該拆。如果拆不開，在描述裡說明為什麼，並標出 reviewer 該重點看
哪幾個檔案。

## 密鑰管理

所有密鑰放 Vault，透過 External Secrets Operator 同步進叢集。程式碼裡不可以有
任何憑證，即使是測試環境的。CI 會跑 gitleaks 掃描，掃到就擋。

本機開發用 `.env`，而且 `.env` 必須在 `.gitignore` 裡。不要把 `.env.example`
填上真實的值。

## 事故處理

事故期間第一優先是止血，不是找根因。先回滾、先切流量，穩定之後再查。

事後一定要寫 postmortem，而且是**對事不對人**的。postmortem 的目的是找出系統
為什麼允許這件事發生，不是找出誰按錯按鈕。範本在 `docs/postmortem-template.md`。
